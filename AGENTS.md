# Architecture Rules

- Separate Natal takeaway actions must use `src/lib/interpretation/takeawayActions.ts` in generators, views, and exports, but never in Chart Walkthrough; why: shared actions stay consistent while practitioner synthesis remains an identity reading rather than a coaching plan.

- All natal psychological-function and aspect interpretation must use `psychologicalFunctions.ts`; this keeps Natal Portrait, Story of Self, and Chart Walkthrough consistent without changing chart calculations.
- All natal house interpretation must use the concrete twelve-house descriptions in `psychologicalFunctions.ts`; this prevents vague house keywords from drifting between reading surfaces.
- Chart ruler = traditional ruler (Mars/Saturn/Jupiter for Scorpio/Aquarius/Pisces), modern ruler named as co-ruler; aspect type = tightest match by true separation. Single sources: `src/lib/interpretation/chartRuler.ts`, `src/lib/aspects/classifyAspect.ts`; why: prevents mislabelled aspects and Pluto-only rulership.
- Element and modality balance copy must use `src/lib/interpretation/elementBalance.ts`; why: keeps low-count behavior, alternatives, and compensation evidence concrete and consistent across natal surfaces.
- The high-level natal synthesis in Natal Portrait and Chart Walkthrough must use `src/lib/interpretation/chartSynthesis.ts`; why: keeps prioritization, evidence, modifiers, and practical translation consistent without changing chart math.
- Natal Portrait and Chart Walkthrough must build and resolve chart selections through `src/lib/charts/chartSelection.ts`; why: prevents hidden duplicates, stale ids, and silent substitution of another person's chart.
- Chart Walkthrough's practitioner presentation and JSON must use `readingGuide/practitionerSynthesis.ts`, deriving identity themes, baseline, and outside/inside contrasts from canonical natal helpers and shared chart synthesis, without action fields; why: preserves a distinct natal identity reading without parallel chart calculations or mismatched exports.
- Developmental Chart Walkthrough sections must use `readingGuide/developmentalSynthesis.ts` with canonical psychological interactions and existing practitioner evidence, never independent geometry or inferred life events; why: UI and JSON share traceable symbolic hypotheses rather than fabricated biography.
- Sign-expression contrasts must consume canonical practitioner evidence through `readingGuide/signExpressionModifiers.ts`, require specific primary modifiers, and retain per-conclusion evidence IDs; why: prevents sign stereotypes, unrelated outer-planet claims, and UI/export drift without changing natal math.

- Solar Return UI and JSON must share `solarReturnEvidenceSynthesis.ts` and `solarReturnProvenance.ts`, with schema validation from the function-shared validator; why: chart identity, separate technique roles, and derived-versus-stored metadata stay consistent without corrupting machine fields.
- Lunar phase labels must use `lunarPhaseConvention.ts`: astrological cycle phase uses the labelled Rudhyar 0-degree-start sectors, and the centred astronomical appearance applies only to a real sky Moon, never progressions; why: cycle phase and visible appearance are different facts and must not be conflated.
- The Natal Portrait "Who This Person Is" reading must be written only from `src/lib/interpretation/chartStoryMap.ts` chains (anchor, ruler, placement, real aspects, tensions, linked transits) and pass `_shared/personReadingValidator.ts` on server and client; why: depth comes from chained evidence, and the validator blocks invented aspects, unknown evidence, fate and diagnostic wording.

- Solar Return solving uses `solarReturnAutoCalculator.ts` and the same apparent Sun longitude from `ephemerisEngine.ts`, preserving unrounded longitudes and withholding houses without an explicit physical return location; why: rounded targets and birthplace substitutions corrupt return times and angles.
- Ask relationship timing uses solver-confirmed `futureTransitScanner.ts` windows and `rulerChains.ts` relevance ordering, with `_shared/verifiedReadingFacts.ts` as a fail-only final gate for Ask and Solar Return prose; why: station minima, generic career ranking, invented ruler chains and unchecked claims must not masquerade as verified relationship evidence.
